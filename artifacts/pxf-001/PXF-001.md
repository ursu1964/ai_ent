# PXF-001 - Scheduler Codex Non-Interactive Invocation Remediation

Result: **IMPLEMENTED_AND_VERIFIED**

Runtime product execution remained stopped. `PRD-TASK-003` was not requeued or executed, no gates were approved, `PRD-DEC-002` and `PRD-DEC-003` remain unresolved, and frozen product plan `PRODUCT-PLAN-7b0342fb7fd5` v1 was not modified.

## Root Cause

PXR-001 isolated attempt 7 to a Codex invocation defect. The scheduler launched:

```text
codex
```

from a non-interactive subprocess. The installed CLI requires the non-interactive form:

```text
codex exec --sandbox workspace-write --ignore-rules -
```

Package construction, runtime binding, worktree creation, timeout policy, and lease release had already passed.

## Remediation

PXF-001 adds a scheduler-safe Codex command resolver:

- `CodexConfig.for_scheduler_from_env()` parses `AIENT_CODEX_COMMAND` and normalizes Codex executables into non-interactive `codex exec` argv.
- `CodexExecutor()` now defaults to the scheduler-safe resolver when no explicit config is injected.
- `GuardedAutonomousRunner`, `ClaimedExecutionRunner`, `scripts/bootstrap.py` guarded execution, and the legacy Codex proof path use the same scheduler-safe resolution.
- Direct bare Codex argv reaching the executor is rejected before subprocess launch.
- Invalid scheduler modes, missing executables, non-executable explicit paths, missing workspace-write sandbox, missing `--ignore-rules`, and missing stdin marker are deterministic configuration errors.

The executor still uses argv form, not shell string interpolation.

## Invocation Contract

The repository-approved scheduler invocation is:

```text
codex exec --sandbox workspace-write --ignore-rules -
```

The package instructions are supplied through `subprocess.run(input=..., text=True)`. The executor cwd remains the isolated execution worktree. The subprocess timeout remains `package.timeout_seconds`, preserving the 1800s PRD timeout and 1860s lease policy.

## Proofs

- argv construction preserves executable paths containing spaces.
- scheduler env `AIENT_CODEX_COMMAND=codex` resolves to non-interactive `codex exec ... -`.
- direct bare Codex executor config is rejected and not launched.

- stdin, cwd, stdout/stderr pipes, and timeout are passed to `subprocess.run` as expected.
- process launch failure, nonzero exit, timeout, and success behavior are deterministic.
